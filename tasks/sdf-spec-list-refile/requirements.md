# Filing handoff requirements (2026-10-06)

The mailbox mechanism and corpus remain in mbox. Kitchen must run the exact
numbered wrapper before issuing a receipt. Bind wrapper, executor, selector,
framer, Kitchen gate, fixture/test bytes and intended argument roles by SHA-256.
Changing any bound bytes or source/destination/mode invalidates the receipt.

Tests run from unrelated directories, including names with spaces. The wrapper
must propagate errors and must not reinterpret copy as move. Inspect and plan
commands never execute a transaction. Live-spool planning must require the exact
incoming spool `/var/mail/isomorphisms`, not the home mailbox.

No live destructive invocation is served: actual NetBSD delivery locks and target
executor acceptance are unqualified. The only mutation wrapper is explicitly
`execute-disposable`, requiring mbox's marked, exclusive disposable workspace.

Receipt qualification is fixture execution, not SDF host acceptance. Hash binding
prevents accidental drift; this is not a signature or protection against a person
forging the receipt. No wrapper beyond the bound artifact is authorized.
