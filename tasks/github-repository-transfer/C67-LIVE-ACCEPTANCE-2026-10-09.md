## Lessons retained from the failed attempts

1. **Do not bypass Kitchen.** The first improvised Bash script ignored the maintained route and never became accepted evidence.
2. **Do not substitute `sh` for Grease.** Shell-compatible fixtures missed real Grease failures including `[` rejection, strict-errexit behavior, ENV access, and native arithmetic.
3. **Materialize before mutation.** Flexible Pipes must fetch, identify, read, generate, parse, and hash every Kitchen standalone program before the first transfer POST.
4. **Observed reads beat redundant access predicates.** On the C67, Grease `test -r` rejected files that `head` had already read. Downloaded programs are admitted by pinned blob identity plus an actual bounded read and exact header.
5. **Keep status and response bytes separate.** Real `gh api` returned nonzero while emitting a 404 REST JSON body on stdout. `$(... || true)` erased the distinction and falsely treated the JSON body as a repository name.
6. **Keep stages distinct.** Visible delivery, device execution, mutation request, per-repository verification, and aggregate verification are separate claims.
7. **Fail without invented success.** Every observed failure stopped before mutation or was independently shown to have made no change. The final success was asserted only after the GitHub postcondition was read.
8. **Use the supported client surface.** For this Android client, ordinary plain text was accepted; fenced code was not. This is an operational fact about this handoff, not proof of a generic trusted chat adapter.
