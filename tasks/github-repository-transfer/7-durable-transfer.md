# Candidate 7: immutable identity and interrupted requests

The six-argument canonical generator selects candidate 7. The original four
arguments plus numeric repository ID and original upstream are bound into the
generated bytes. `-` selects a nonfork. The inherited four-argument interface
continues selecting candidate 6 for historical consumers; it does not qualify
for this new handoff. Candidate 6's known absence of durable POST state and
explicit upstream pins is not silently rewritten.

FP supplies an absolute persistent state directory and one of preflight,
execute or verify. A directory created atomically before the POST records that
the request may have reached GitHub. Failure, interruption and timeout never
erase it. A retry can observe completion, but cannot issue another POST.
Ambiguous failures therefore deliberately prefer refusal over duplicate effects.

Every API request retains stdout, stderr and process status. Each repository
identity check uses one response for ID, canonical name, fork and parent/root.
The current contract expects the immediate parent and original root to equal
the explicit upstream; fork-of-fork inputs with differing parent/root refuse.

AI-CI's native Grease tests execute generated bytes with external GitHub
fixtures, including interruption and later convergence. These are Linux host
tests. They do not prove C67 execution, real GitHub mutation or trusted delivery.
