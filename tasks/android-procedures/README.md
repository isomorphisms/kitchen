# Maintained Android procedure family

Status: HOST_FIXTURE candidate. Android materialization, installation and registered
FP integration are BLOCKED on verified CF-A2-S2/S3/S4 contracts. This file never
declares a new Cat Food installer, hardware registry, plan schema or producer.

The immutable source registry is `procedures.tsv`. Installed runtime paths belong
to Cat Food. A runtime manifest is a strict TSV of `role`, absolute regular-file
path and SHA-256. It covers the complete selected runtime closure and every owner
adapter. Its digest is bound in the reviewed procedure contract. Resolving that
manifest from Cat Food is a prerequisite, not a Kitchen checkout-discovery step.

Version 1 has finite `materialize`, `install-update`, and `capture` operations.
All invoke the same `1-run.grease` and `1-run.pi`. Manual/registered routes pass
the same input bytes and invoke the same owner adapter bytes; their final receipts
distinguish scope. Registration is a declared HOST_FIXTURE invocation binding,
not a claim that Flexible Pipes authorized or observed a physical execution.

The host candidate wrapper receives absolute checked-Ithon runtime and owner
paths, followed by their reviewed digests. It hashes both before executing the
owner in a cleared environment. The owner receives explicit absolute inputs and
independently supplied digests for contract, plan, profile, application
requirements, runtime configuration and payload location, plus manifest, route
and new output directory. Registered scope also requires a digest-bound
registration with the same contract/plan/profile and invocation identifier.

Each adapter receives only the fixed operation, immutable input snapshots,
their digests, a new postcondition destination, and the prior owner receipt.
Admission precedes executor effects. Independent validation follows executor
success. These are provisional fixture adapter calls; S3 must supply and qualify
the actual maintained Cat Food entrypoints before a production version is made.

Failures before output creation leave no output. Later failures retain a FAILED
receipt, bounded stdout/stderr/status files and partial results. Nonzero exit,
timeout, changed bytes, missing/partial postconditions, a rewritten owner receipt,
or a failed validator cannot become PASS. A failed installation can have partial
device effects; Kitchen never claims rollback. No uninstall fallback exists.

Capture version 2 lives in `../android-diagnostic/2-capture.pi`, separately from
the retained version 1. It probes current model, explicit serial-property domain,
firmware and ABI, requires expected version/APK, bounds all channel calls, and
rechecks PID/start identity, APK path/digest and handset facts. It supports the
existing finite frame/crash/zoom observations. APK source association still
requires S4 producer evidence; a log or screenshot does not prove cause or repair.

Prebuilt capture candidates need a declared Python runtime at the native
launcher's compiled path, the delivered checked-Ithon closure, bounded-process,
an explicitly verified ADB or rish runtime, and rish DEX when selected. Missing
runtime is a refusal, never phone-side compilation. File digests do not prove
Shizuku authorization or service availability. Candidate archives are not
registered with Cat Food until its independent acquisition/receipt contract can
validate them. Pre-Grease acquisition remains Cat Food's finite existing seam.

Reproduction is recorded in `qualification.md`; the tests take explicit runtime
and artifact paths and create fresh output, so they can run without a checkout
working directory. The fixtures are independent native simulations and bounded
real host subprocesses; they do not implement actual Android installation policy.
Leaf build semantics remain in leaf owners. Kitchen's separately versioned build
adapter preserves the existing off-device NDK recipe; S4 ICK fallback authority
and Android producer qualification remain blocked.
