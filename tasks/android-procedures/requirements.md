# Android procedure family, candidate version 1

Kitchen owns this versioned invocation boundary, not package installation,
device selection, application build semantics or producer authority. Cat Food
supplies immutable opaque plan, profile, application requirements, payload
location and runtime configuration files. No hardware table lives here.

The identical acquired Grease wrapper and checked Ithon owner are used by a human
and a registered Flexible Pipes execution. Registration changes receipt scope,
never selects different implementation bytes. Registration must bind the same
contract, plan and profile; it is a declared fixture scope, not authentication.

Before any adapter executes, require absolute nonsymlink regular files, strict
unique TSV contract fields, independently supplied digests for all input files,
and a closed exact-byte manifest covering the wrapper, engine, Ithon/Grease
runtime closure and owner adapters. Copy immutable data to private scratch and
recheck input and executable bytes before and after every stage. Work from an
unrelated directory with a minimal environment; no ambient PATH, module path,
runtime selector, repository checkout or hardware override may change behavior.

The finite operations are materialize, install-update and capture. Each uses
Cat Food admission, one maintained owner executor and Cat Food independent
receipt validation. Payload URI is opaque data passed to Cat Food; Kitchen
never interprets a URI as a local pathname or invents a download location.
Installation is delegated, with no uninstall, signer bypass or downgrade flag.
Capture delegates the versioned read-only Kitchen capture adapter. Leaf build
semantics remain in the leaf; this boundary invokes no build tool on Android.

Zero exit alone is insufficient. Admission and independent validator must emit
strict typed postconditions bound to contract, plan, profile, requirements,
runtime and payload-location digests. Nonzero exits, timeout, changed bytes,
missing/partial receipts and receipt binding mismatch remain failures. A
validator failure never becomes success through the Grease wrapper. Capture
fixtures must preserve a synthetic device-state sentinel. Effects after a
successful admission cannot be rolled back or misreported as never attempted.

Candidate version 1 permits HOST_FIXTURE only. Android admission is BLOCKED
until verified S2 plan/profile, S3 installation/receipt and S4 producer outputs
exist. A caller-provided PASS flag cannot enable Android. This candidate adapter
protocol is not presented as a new Cat Food plan or accepted production schema.

Fixtures precede implementation. Run every route twice from unrelated working
directories after clearing ambient state, including changed script/runtime/
payload/input, wrong handset/ABI, stale profile, URI/path confusion, failed
install, signer/downgrade refusal without uninstall, validator failure,
timeout and partial output. Real capture process/service cases are covered
separately by the version 2 capture suite. Host fixture acceptance is never
installed runtime availability or physical behavior.
