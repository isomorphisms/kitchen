# CGW-FC-01 native capture qualification

Target: positively identified Ubuntu x86-64 build host. Synthetic loopback TLS
only; no session, real account, live export, phone or tablet. No model dispatch,
merge, release or tracker closure. Cat Food retains device ownership.

Before effects, require exact clean exporter/ai-ci/Kitchen/Ike revisions,
absolute observed roots and source-qualified ICK and Grease executables.
Provisioning is a separate producer stage. This task installs nothing and has
no compiler, shell, credential or network fallback.

Use the checked-in Ikefile through actual source-pinned Ike with a caller-bound
Ikefile digest and Grease recipe runner. Keep the existing native planner,
private store, TLS and TypeScript tests. New capture must execute main and
archived pages through TLS into private raw objects; prove empty histories,
termination probes, stable repeated inventory and durable complete markers.
Adverse cases include overlap/conflict, totals/offset drift, malformed JSON,
graphs, HTTP failures, token reflection, byte/work limits, corrupt hashes,
private mode/symlink rejection, interruption, kill/restart and partial account
reporting. Premature completion, omitted records, invalid marker reuse and
skipped workflow triggers must be rejected by their relevant tests.

ai-ci owns the independently compiled raw/semantic oracle and receipt check;
the capture cannot accept itself. Output identities, modes, source and binary
SHA-256, exact producer receipts and bounds must remain available. Source
qualification, host fixtures, loopback capture, Android packaging and physical
behavior are separate evidence categories. A source preflight cannot certify
the inactive production FP controller or an absent visible-sink receipt.
