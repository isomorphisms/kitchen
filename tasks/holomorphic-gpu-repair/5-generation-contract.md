# Candidate 5 generated-source stages

Inputs extend the earlier exact-source handoff with an `idric` source row,
an exact `ick` executable, a declared host linker and `shader-validator`.
The context's source/material hashes must include the maintained application
shader and the native generated-byte verifier. The existing control envelope
remains https://github.com/isomorphisms/flexible-pipes/issues/227.

1. `compiler-bootstrap`: archive the pinned Idriç source into isolated run output
   and invoke its own `edric bootstrap` with the qualified ICK compiler. Record
   the compiler, Chez and complete generated compiler payload hashes.
2. `compiler-api`: install the owner's compiler API using that same built
   compiler, prefix and Chez executable. Check the compiler payload hashes.
3. `generated-compiler`: archive the pinned backend, copy the exact maintained
   application shader source, build the backend with the matching API, emit the
   fragment, require its complete application uniform interface and run GLSL
   validation. Preserve actual source/compiler/fragment hashes and provenance.
4. `generated-binding`: create the header from actual generated bytes, compile
   the app's native verifier through ICK, execute it on the actual fragment and
   receipt, then reject an executed changed-byte/unchanged-receipt mutation.

The original checkouts remain unchanged because bootstrap/build outputs live in
the run context. Each operation is an actual Ike target under the selected
Grease interpreter. A host compiler/source-binding result does not inherit APK,
installation, emulator, GPU numerical, colour parity or performance acceptance.
