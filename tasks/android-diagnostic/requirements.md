# Identity-bound Android observation

Input is a prepared AICI claim contract and a selected Cat Food profile. No
package discovery result may implicitly select an application. Original and
inspection Halite may coexist. Resolve package, APK digest, version, process
start, current authority and session before capture; recheck process and APK
after capture. Never pass an absent or multiple PID to logcat.

An absolute rish launcher or an absolute ADB client plus explicit serial is
deployment configuration. rish files/DEX, authorization/service, effective UID,
ADB host server and connected Android device are separate observations. The
Android shell is an externally fixed platform-command boundary. Its payloads
invoke absolute system commands, with validated identifiers and no pipelines.

Capture is private and bounded. Default effects are observation only. Empty
logs, failed producers, process exit/reuse, permission denial, timeout and
interruption cannot yield bound success. Missing application telemetry blocks
zoom-state claims, but a weaker requested screenshot remains useful.

The fresh-consumer suite executes exact acquired task bytes twice from unrelated
directories with a cleared environment. Fixtures are host evidence, never phone
acceptance. They must include launcher-without-service, original/inspection
ambiguity, wrong package, absent/multiple/changing PID, empty logs, producer
failure, timeout, permission denial, swapped APK and valid counterparts.
